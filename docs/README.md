## Documentation Scope

This documentation describes the current technical and visual architecture of the Ristorante Incontro Limone website.

The documentation covers:

* project architecture
* design system
* internationalization
* deployment
* development constraints
* implementation principles

The documentation should evolve together with the project.

---

## Source of Truth

The GitHub `main` branch is the source of truth for the current project state.

Documentation must describe the actual implementation.

When the architecture, design system, internationalization or deployment process changes, the relevant documentation must be updated.

Documentation must not describe planned or hypothetical functionality as if it were already implemented.

---

## Project Development

Ristorante Incontro Limone is an actively developed project.

The existing technical architecture should be preserved while the project is progressively adapted and finalized.

Changes should be incremental and limited to the requested scope.

Avoid unnecessary:

* rewrites
* framework migrations
* architectural changes
* broad refactoring
* removal of working functionality

When a significant architectural decision is introduced, update the relevant documentation.

---

## Documentation Principles

Project documentation should:

* describe the current implementation
* remain consistent with the repository structure
* use the current project identity
* avoid obsolete project references
* avoid unverified technical assumptions
* remain concise and practical
* be updated when significant changes are introduced

Documentation is part of the project and serves as a technical reference for future development.
